隐私政策

生效日期：2026 年 11 月 8 日　｜　最近修订：2026 年 11 月 12 日（1.5.1：按真机反馈修复右下角水印漏检，重写本机水印检测与条带重建；数据流向、权限与接收方不变）　｜　适用版本：1.5.1（历史版本 1.4.2 及以上同样适用）　｜　开发者：TapeOut 社区 · 昆哥
一句话总结： 扩展本身没有服务器、没有账号体系、没有统计或遥测。「一键转发」的提取、去水印、剪贴板与下载全部在本机完成，不上传任何数据。AI 功能默认走「X 站内直连」（免 API Key）：由你已打开的 X 页面，以你已登录的会话直接向 X 自有的 Grok 接口发送「设定提示词 + 你选中的推文正文或待核验链接」，接收方仅 X/Grok，扩展后台只接收生成的 3 条文本候选；只有你主动切换到「xAI API」模式并填写自己的 Key 时，接收方才改为 xAI。为让 X 认可是自己网页客户端发出的请求，页面内脚本会在本机读取 ct0 认证 Cookie 与 authorization bearer，这些值仅留在该页面内存，不存储、不导出、不回传给开发者。不使用 AI 功能时不会发起任何相关请求。

1. 我们会处理哪些数据

仅在你主动点击页面上的「一键转发」「AI 评论」或生态面板的「核验链接」时，扩展才读取下列内容：

  • 当前这条内容的正文文字（转发时用于清洗后预填到 X 发推框；AI 评论时用于生成回复候选，截断至最多 1200 字符）；
  • 这条内容的配图与视频直链地址（仅用于下载到本地、写入剪贴板或在本地做去水印）；
  • 这条内容的固定链接与公开标识（用于可选的原推链接标注、回复目标定位、文件命名）；
  • 你在生态面板输入框里粘贴的待核验链接；
  • 页面 DOM 结构（用于定位正文、内容图与插入按钮）。

扩展不会读取与你正在操作的内容无关的标签页，不会读取密码、表单输入，不建立浏览历史（访问列表 / 页面标题 / 访问时间）记录，也不会上传图片或视频文件。

认证凭证（如实披露）：仅在「X 站内直连」模式下，页面内脚本会读取 X 的 ct0 认证 Cookie（用作 x-csrf-token），并通过轻量包装 window.fetch 观察 X 自身请求头中的 authorization bearer 与 x-client-transaction-id，用于把 Grok 请求发回 X 自己。这些值只存在于该 X 页面的内存变量中，不写入 chrome.storage / localStorage、不导出、不上传给开发者或任何第三方，接收方始终只有 X/Grok；扩展不读取你的密码、PIN 或安全问题。因官方把 authentication cookies 归入「Authentication information」，且本地处理同样需要披露，商店 Privacy practices 中已勾选该项，并同时勾选「User activity」（fetch 请求头观察）与「Website content」。

2. 数据存到哪里

  • 偏好设置（去水印开关、站点开关、署名开关、提示词等）保存在 chrome.storage.sync；若你开启了 Chrome 同步，浏览器会按你自己的同步设置同步这部分偏好。
  • xAI API Key 与接口配置（模型、协议、网关地址）保存在 chrome.storage.local，仅存本机、不同步、不随扩展分发，只用于向你指定的接口发起带 Authorization 头的请求。开发者无法读取它。
  • 处理后的图片写入系统剪贴板，或按你的操作下载到本机下载目录；文件名前缀为 xpost_。
  • 文字只通过 URL 参数预填到 x.com/intent/tweet 或 twitter.com/intent/tweet 的新标签页，由你手动点击发送。扩展不调用任何发布接口，也不会替你发帖或回复。
  • 生态收录清单（295 条）是内置在扩展代码里的静态数据，来源为 TapeOut.link 公开的站点数据与 web.tapeout.link 的 DeWeb 索引（核验日期 2026-11-08），不会联网拉取，也不包含你的任何信息。
  • 1.4.13 行情数据（仅存本机）：价格上下限、提醒开关、检查间隔等偏好保存在 chrome.storage.sync；最近一次行情快照、提醒状态机、系统通知 id 与交易所链接的对应关系保存在 chrome.storage.local。这些值只含公开行情数字与你自己填写的阈值，不含任何账号、身份、页面内容或浏览历史，也不会上传给开发者或第三方。可在面板「价格提醒设置」里关闭提醒或清空阈值。

我们（开发者）不运营任何后端服务，因此无法访问、收集、存储或分析上述数据。

3. 网络请求

转发链路：扩展会向内容所在的图片/视频 CDN 发起请求以下载媒体（例如 sinaimg.cn、zhimg.com、qpic.cn、hdslb.com、doubanio.com、xhscdn.com、twimg.com）。为通过图床防盗链校验，扩展会用 declarativeNetRequest 为这些请求设置对应站点的 Referer 请求头。微博视频会优先查询公开的 m.weibo.cn/statuses/show 接口获取高清地址（请求中仅包含该条内容的公开 ID）。

AI 链路（仅主动使用时）：见下节。

1.4.13 行情链路（后台定时，纯只读）：为在面板顶端显示三项公开行情，扩展后台默认每 5 分钟（可设 1 / 5 / 15 / 30 分钟，也可手动点 ↻ 立即刷新）向以下两个公开只读接口发起 GET 请求。其中 $BEM 与矿机日产能价这两项数据都来自 Firsto（接口域名 api-tapeout.firsto.ai，数据页 tapeout.firsto.ai）；第三项 TapeUP 内盘价来自 tapeup.io，见下一段，与 Firsto 无关：

  • https://api-tapeout.firsto.ai/v1/analytics/bem?range=24h 与 /v1/circuit-holders?page=1：$BEM 现价与 TapeOut 矿机日产能价（后台 GET）。后者是 https://tapeout.firsto.ai/circuits/other 页顶「日产能价参考价」所用的同源公开接口；1.4.20 起替换原来的 /v1/analytics/circuits?range=24h（24h 成交序列，会滞后）。接口路径变了，但域名、请求方式与只读性质不变；

1.4.16 TapeUP $UP 内盘价（内容脚本采集，非后台 GET）：tapeup.io 整站 Cloudflare 防护，后台直接 fetch 会被拦，因此 TapeUP $UP 的内盘价（页面标注 BEM/UP，即 UP 以 BEM 计价，如 0.0264 BEM/UP，并同时给出美元折算价 $0.3181；来自 https://tapeup.io/zh/trade/token?id=1）改由扩展的内容脚本在你已通过 CF 的浏览器会话里读取页面显示的内盘价，再回传后台缓存。1.4.21 起只按页面上的 BEM/UP 标签与「价 + 美元 + 百分比」组合定位价格，钱包余额、待释放余额、统计区数字与图表坐标只作本机诊断候选、不参与取价；认不出就显示未采集。扩展仅在 tapeup.io 注入内容脚本读取该页显示的价格数字，不读取页面外数据、不发送任何本机数据、不在该域发起额外网络请求。

请求仅携带 Accept: application/json 与 cache: no-store，不携带 Cookie、认证头、API Key、页面内容、推文正文、用户标识或任何本机数据；接口不要求登录，响应只含公开行情数字。点行情卡片或点提醒弹窗时，浏览器会打开 https://firsto.ai/data、/data/bem，或（1.4.20 起矿机卡）https://tapeout.firsto.ai/circuits/other 这类普通网页，该页面由 Firsto 运营，其后产生的访问遵循 Firsto 自己的隐私政策；扩展不会替你登录、下单或提交任何表单。链接经本机白名单校验，只放行 firsto.ai 及其子域与 tapeup.io 及其子域。

1.4.14 签名帧（仅本机 DOM）：站内直连的 x-client-transaction-id 需要 X 自带签名模块读取 X 首页下发的 4 个加载动画 SVG 的几何数据。扩展会以你已登录的会话读取一次 https://x.com/ 的 HTML（GET，接收方仅 X），只取这 4 个帧的 path 数据，并在当前 X 页面临时插入隐藏帧供签名模块读取，签名完成后立即移除。该过程不读取页面文字、推文内容或账号信息，不新增网络接收方，也不上传任何数据。

扩展没有分析、广告或跟踪代码，没有远程加载的脚本，也不连接开发者自建的服务器。

4. AI 功能：运行模式与数据流向

两个由你手动触发的 AI 功能（X 一键评论、链接真伪查询）支持「自动（默认）／站内直连／xAI API／页面模式（1.4.0 起已弃用，仅手动兜底）」。默认「自动」在未填 API Key 时走 1.4.2 的站内直连：由 X 页面自身向 X 自有的 Grok 接口发请求；填了 Key 才走 xAI API。

① API 模式（xAI Grok）：需要你自己的 xAI API Key，扩展后台才会向 https://api.x.ai/v1（或你自填的兼容网关）发起请求：

  • X 一键评论：点击后把该条推文的正文 + 你设定的评论提示词发送给 https://api.x.ai/v1（或你在设置里填写的兼容网关），由 Grok 生成 3 条回复候选。候选只显示在本机浮层里；选中后才写入当前 X 回复框（1.3.1 起按钮位于回复填写区右侧，写入是页面内 DOM 操作，不产生新的网络请求），发送由你手动完成。
  • 链接真伪查询：点击核验后把待核验链接 + 插件本地比对得出的结论 + 与本次判定相关的少量清单条目 + 你设定的核验提示词发送给同一接口，由 Grok 生成解释与仿冒风险判断。最终是否给绿标由本地清单决定，不采信模型结论。

② 页面模式（1.3.0 引入，1.4.0 起已弃用，仅作手动兜底）：扩展不向 xAI 或任何 AI 接口发送网络请求，也不读取 X 登录凭据。它只在你已登录的 x.com/i/grok（或 X 页面上的 Grok 浮窗）里，把设定好的提示词填入输入框、按需点击发送，并从该页面读取 Grok 回答的文本，在本机解析成候选。与 Grok 的对话由 X 自己完成并保存在你的 X 账号里，受 X 的服务条款与隐私政策约束；扩展不读取你的对话历史、其它标签页或账号信息。仅当你显式切到该模式、或站内直连与 API 都不可用时使用；此模式不产生 API 调用费用。

若自动发送或读取失败，可改用手动流程：插件只把提示词填进输入框 / 复制到剪贴板，由你自己粘贴发送，回答出来后再点「读取 Grok 回答」。所有 DOM 选择器都可在设置里修改。

1.3.2 起的结果校验：页面模式会用唯一任务标记确认提示词确实只写进了 Grok 输入框、确实被发送，并确认读回了回答块；任一环节不成立就明确报错，不会把 X 页面的侧栏文字或按钮文字当作 Grok 结果展示。点击后出现的等待浮层只显示进度与耗时，不上传任何数据；Grok 回答文本的解析全部在本机完成。

1.4.2 起的认证修复与同页通道复用：若用户在同一 X 页面另行安装了 X Viral Monitor，扩展可能优先调用它已暴露在页面内的 Grok 生成函数；该调用仍发生在用户本机浏览器里，请求接收方仍只有 X / Grok（同为 grok.x.com/2/grok/add_response.json，发送提示词与推文正文），不新增第三方接收方、不新增网络请求类型、不把会话或内容回传给 TapePost 服务器或该插件开发者，扩展后台仍只接收 3 条文本候选。401 / 403 时扩展会读取 X 返回的错误说明用于本机排错，并可能用 X 网页客户端公开 bearer 重试一次；错误说明只在本机显示，不上传。

1.4.1 起的运行模式自动纠正：旧版可能把「X 站内 Grok」保存为已弃用的「页面模式」，导致站内直连不生效。1.4.1 会在设置面板与后台读取配置时把该旧值按「自动 · 优先站内直连」处理，并可选择一次性写回本机设置（仅修改运行模式这一项，并写入一个一次性标记，用户之后主动选择不会被覆盖）。该过程完全在本机完成，不新增网络请求、不上传任何数据；对 X/Grok 的数据流向与本页 1.4.0 段落所述一致。

1.4.0 起的站内直连（请重点阅读）：「自动 / 站内直连」模式下，AI 评论与链接核验会以你当前已登录的 X 会话，从 X 页面直接向 X 自有的 Grok 接口 grok.x.com/2/grok/add_response.json 发送「提示词 + 你选中的推文正文或待核验链接」。随请求发送的是浏览器自动附带的 X 会话 Cookie 与 X 网页客户端固定请求头（含 ct0、authorization、x-client-transaction-id）；签名在你本机页面内由 X 自带模块生成，不经过 TapePost 服务器、插件后台或任何第三方，扩展后台只接收生成的 3 条文本候选。数据接收方仅为 X / Grok，受 X 的条款与隐私政策约束；对话被设为临时对话（isTemporaryChat），不写入你的 Grok 历史。若你填写 API Key 并切到「xAI API」模式，接收方改为 xAI（api.x.ai）；若使用旧的「页面模式」，对话发生在 X 页面内，扩展自身不新增网络请求。插件不读取你的 X 密码，也不做遥测；但会在该 X 页面内读取 ct0 认证 Cookie 并观察 X 自身请求头中的 authorization bearer 以复用会话（仅页面内存、不存储、不导出、不回传给开发者或第三方，接收方仅 X 自己），详见第 1 节与第 5 节。

1.3.4 起的正文清洗（仅指清洗步骤本身）：回复框内的按钮去重、插件界面文字剥离、推文正文提取全部在页面内 DOM 完成，不涉及任何网络请求、不新增第三方接收方、不上传推文正文或页面内容；清洗后只剩界面文字时扩展会取消生成并在本机提示，不会把该内容发送给 Grok。

1.3.3 起的连接自愈：重新加载扩展后，插件可能刷新已打开的 X / Grok 标签，或在后台新建 x.com/i/grok 标签，以恢复失效的页面内脚本。刷新与新建标签均为浏览器本地操作，不会上传页面内容、推文正文、X 登录凭据或任何其它数据，也没有新增第三方接收方；连接错误只在本机转成中文提示，不回传诊断信息。

生态面板的 295 条收录清单是内置在扩展里的静态数据：运行时不会访问 tapeout.link 或 web.tapeout.link 拉取清单，也不会把整份清单上传给 xAI；核验时只发送你输入的链接、本地结论和上述少量相关条目。

不会发送给开发者或任何第三方：浏览历史、其它标签页内容、图片/视频文件、账号密码、个人信息，以及认证凭证的副本或日志。需要区分的是：站内直连的请求由浏览器自动携带 X 会话 Cookie 与请求头（含 ct0、authorization）发给 X 自己（接收方仅 X/Grok），这是 X 网页客户端发请求的正常行为；扩展不存储、不导出、不回传这些值，也不会把它们发给除 X 之外的任何一方。页面模式同样不会把回答文本上传给任何服务器 —— 解析全部在本机完成。

第三方责任：API 模式下发送给 xAI 的内容受 xAI 的隐私政策与其服务条款约束，调用额度与费用由你自行承担；若填写第三方兼容网关，该网关运营方同样会收到内容，请先确认你信任它。站内直连与页面模式下，提示词与回答由 X 处理，受 X 的隐私政策与服务条款约束。扩展开发者在任何模式下都不接收、不留存这些内容。

你可以在设置面板里切换运行模式、删除 API Key、关闭「自动发送」或关闭「AI 评论」按钮。删除 Key 后 AI 功能会自动改用 1.4.2 的站内直连；只使用「一键转发」时扩展完全离线可用。站内直连需要 Chrome 已登录 x.com 且账号具备 Grok 权限。

隐私政策

生效日期：2026 年 11 月 8 日　｜　最近修订：2026 年 11 月 14 日（1.5.8：钱包资产在 BSC 之外增列 X Layer 的 $FAB 余额、电路矿机、待领与 OKB；新增 api.fabx.tech、rpc.xlayer.tech、xlayerrpc.okx.com 三条主机权限（合计 36 条），数据流向见第 3 节。此前 1.5.7：信仰者昵称与内置头像可随时修改并保存；当天已投支持票时，改动会同步更新公开账本上对应的明细，断网则联网后补投；不新增数据种类、权限或接收方。此前 1.5.6：$BEM 打卡改为「连接钱包后才能投支持」，支持票会公开发布昵称、内置头像编号、北京时间与随机激励话语；身份哈希改为「钱包地址 + 日期」的 SHA-256；新增 10000 条本机激励话语文库与一键发到 X。数据流向见第 3 节。此前 1.5.5：行情改为 BEM 置顶大数字、描述文字缩小；新增只读钱包连接（OKX 欧意 / 币安 Web3 / TokenPocket / MetaMask 等注入式钱包，地址 AES-GCM 加密仅存本机）、基于 TapeOut API v1 与 TapeAPI 3.0.0 的钱包资产读取、$BEM 信仰者每日打卡与全网共享账本。新增 scripting / activeTab 两项权限与 api.tapeapi.fun、tapeout.firsto.ai、账本服务三条主机权限，数据流向见第 3 节。此前 1.5.4 修复微博视频帖入口、1.5.3 新增 DeepSeek API 模式）　｜　适用版本：1.5.8（历史版本 1.4.2 及以上同样适用）　｜　开发者：TapeOut 社区 · 昆哥
一句话总结： 扩展本身没有账号体系、没有统计或遥测，除 1.5.5 新增的 $BEM 投票共享账本外没有其它服务器。「一键转发」的提取、去水印、剪贴板与下载全部在本机完成，不上传任何数据。AI 功能默认走「X 站内直连」（免 API Key）：由你已打开的 X 页面，以你已登录的会话直接向 X 自有的 Grok 接口发送「设定提示词 + 你选中的推文正文或待核验链接」，接收方仅 X/Grok，扩展后台只接收生成的 3 条文本候选；只有你主动切换到「xAI API」或「DeepSeek API」模式并填写自己的 Key 时，接收方才改为对应服务商（xAI 或 DeepSeek）；两家的 Key 与配置分开保存，同一时刻只会向你选定的那一家发请求。为让 X 认可是自己网页客户端发出的请求，页面内脚本会在本机读取 ct0 认证 Cookie 与 authorization bearer，这些值仅留在该页面内存，不存储、不导出、不回传给开发者。不使用 AI 功能时不会发起任何相关请求。1.5.5 起：只读钱包绑定会把一个公开地址用 AES-GCM 加密存在本机，加密密钥同样只在本机；扩展不接触私钥 / 助记词、不签名、不发交易。读取资产时会把这个公开地址发给 Firsto 的 TapeOut API 与 TapeAPI 公共签名读取服务（只读，不含身份信息）。$BEM 信仰者打卡必须先连接钱包，会向一个公开的共享账本提交「日期 + 立场 + 钱包地址哈希 + 你主动填写/抽取的昵称、内置头像编号、打卡时间与一句激励话语」，这些内容会在账本公开页展示；明文钱包地址绝不上传；该账本由开发者运营，除此以外扩展仍无账号体系、无统计或遥测。1.5.7 起昵称与头像可随时修改并保存，当天已上墙的支持票明细会同步更新。1.5.8 起钱包资产除 BSC 的 $BEM / 矿机外，还会把同一个公开地址在 X Layer 上的 $FAB 余额、电路矿机、待领 FAB 与 OKB 余额一并只读罗列；为此新增 FabX 官方 PoD 索引与 X Layer 公共 RPC 两个数据接收方，两者都只收到公开地址与公开合约地址，不接收任何身份信息，详见第 3 节。

1. 我们会处理哪些数据

仅在你主动点击页面上的「一键转发」「AI 评论」或生态面板的「核验链接」时，扩展才读取下列内容：

  • 当前这条内容的正文文字（转发时用于清洗后预填到 X 发推框；AI 评论时用于生成回复候选，截断至最多 1200 字符）；
  • 这条内容的配图与视频直链地址（仅用于下载到本地、写入剪贴板或在本地做去水印）；
  • 这条内容的固定链接与公开标识（用于可选的原推链接标注、回复目标定位、文件命名）；
  • 你在生态面板输入框里粘贴的待核验链接；
  • 页面 DOM 结构（用于定位正文、内容图与插入按钮）。
  • 1.5.5：你主动点「连接钱包」时由已安装钱包返回的一个公开钱包地址（或你手动填入的地址）与其链 ID；不读取私钥、助记词、签名内容、交易记录或钱包里的其它账号；
  • 1.5.6：你主动点「支持 / 观望」时的当日打卡立场（support / watch），以及由「钱包地址 + 日期」经 SHA-256 得到的当日身份哈希（不可逆、每天轮换、不含明文地址）；不读取设备标识或其它账号；
  • 1.5.6：你主动填写的信仰者昵称（≤16 字）、从 32 款内置头像里选的编号、打卡时间（北京时间），以及从本机 10000 条话语文库里随机抽中的一句激励话语——这四项会随支持票写入公开账本并在 /vote 页展示；观望票不上墙；
  • 1.5.6：你主动点「𝕏 发布到 X」时，上述话语与昵称、时间、账本链接会被预填到 X 发推框；发送由你手动完成，扩展不读取你的 X 账号信息。

扩展不会读取与你正在操作的内容无关的标签页，不会读取密码、表单输入，不建立浏览历史（访问列表 / 页面标题 / 访问时间）记录，也不会上传图片或视频文件。

认证凭证（如实披露）：仅在「X 站内直连」模式下，页面内脚本会读取 X 的 ct0 认证 Cookie（用作 x-csrf-token），并通过轻量包装 window.fetch 观察 X 自身请求头中的 authorization bearer 与 x-client-transaction-id，用于把 Grok 请求发回 X 自己。这些值只存在于该 X 页面的内存变量中，不写入 chrome.storage / localStorage、不导出、不上传给开发者或任何第三方，接收方始终只有 X/Grok；扩展不读取你的密码、PIN 或安全问题。因官方把 authentication cookies 归入「Authentication information」，且本地处理同样需要披露，商店 Privacy practices 中已勾选该项，并同时勾选「User activity」（fetch 请求头观察）与「Website content」。

2. 数据存到哪里

  • 偏好设置（去水印开关、站点开关、署名开关、提示词等）保存在 chrome.storage.sync；若你开启了 Chrome 同步，浏览器会按你自己的同步设置同步这部分偏好。
  • xAI / DeepSeek 的 API Key 与接口配置（模型、协议、接口地址、网关地址，1.5.3 起两家的密钥分别存放、互不覆盖）保存在 chrome.storage.local，仅存本机、不同步、不随扩展分发，只用于向你指定的接口发起带 Authorization 头的请求。开发者无法读取它。
  • 处理后的图片写入系统剪贴板，或按你的操作下载到本机下载目录；文件名前缀为 xpost_。
  • 文字只通过 URL 参数预填到 x.com/intent/tweet 或 twitter.com/intent/tweet 的新标签页，由你手动点击发送。扩展不调用任何发布接口，也不会替你发帖或回复。
  • 生态收录清单（295 条）是内置在扩展代码里的静态数据，来源为 TapeOut.link 公开的站点数据与 web.tapeout.link 的 DeWeb 索引（核验日期 2026-11-08），不会联网拉取，也不包含你的任何信息。
  • 1.4.13 行情数据（仅存本机）：价格上下限、提醒开关、检查间隔等偏好保存在 chrome.storage.sync；最近一次行情快照、提醒状态机、系统通知 id 与交易所链接的对应关系保存在 chrome.storage.local。这些值只含公开行情数字与你自己填写的阈值，不含任何账号、身份、页面内容或浏览历史，也不会上传给开发者或第三方。可在面板「价格提醒设置」里关闭提醒或清空阈值。
  • 1.5.5 钱包地址（加密、仅本机）：公开地址与所用钱包名称、链 ID 一起用 Web Crypto AES-GCM 加密后存 chrome.storage.local；32 字节密钥在安装时由本机随机生成，也只存本机、不同步、不随扩展分发。点「断开」即删除密文与资产缓存。扩展不保存明文地址、不接触私钥 / 助记词，也不请求签名或交易授权。
  • 1.5.5 投票与资产缓存（仅本机）：打卡历史（哪天投了什么立场）、待补投票、最近一次全网账本快照、资产快照、账本地址与提醒时间都存 chrome.storage.local；不含身份信息，也不含钱包地址。账本地址可在设置里改成你自己的兼容服务。1.5.6 起另在 chrome.storage.local 保存你的信仰者名片（昵称 + 内置头像编号）与最近抽中的一句激励话语，仅存本机、不同步，可在弹窗里随时修改。1.5.7 起输入停顿、失焦、回车或点「💾」都会立即保存；若当天已投支持票，改动会用同一身份哈希向账本重提一次相同的四类内容，以更新公开墙上对应的那一条（激励话语与时间沿用原值，不重复计票）；断网时更新包暂存本机待补投队列，联网后再同步。1.5.8 起资产快照同时包含 X Layer 的公开余额、矿机数与算力数字，仍只存本机、不含钱包地址明文；加载新版本后首次打开弹窗会自动补取一次双链快照。

除第 3 节披露的「$BEM 信仰者投票共享账本」外，开发者不运营任何其它后端服务，也不设账号体系、统计或遥测；该账本 1.5.6 起还会接收并公开展示你主动填写的昵称、内置头像编号、打卡时间与随机激励话语，以及不可逆的地址哈希；不接收明文钱包地址、API Key、页面内容、推文正文或设备标识。因此开发者无法访问、收集或分析上述本机数据。

3. 网络请求

转发链路：扩展会向内容所在的图片/视频 CDN 发起请求以下载媒体（例如 sinaimg.cn、zhimg.com、qpic.cn、hdslb.com、doubanio.com、xhscdn.com、twimg.com）。为通过图床防盗链校验，扩展会用 declarativeNetRequest 为这些请求设置对应站点的 Referer 请求头。微博视频会优先查询公开的 m.weibo.cn/statuses/show 接口获取高清地址（请求中仅包含该条内容的公开 ID）。

AI 链路（仅主动使用时）：见下节。

1.5.5 只读钱包连接（用户主动点击才发生）：点「连接钱包」后，扩展用 chrome.scripting 在当前这一个标签页的页面环境里探测 EIP-6963 / EIP-1193 注入式钱包（OKX 欧意、币安 Web3、TokenPocket、MetaMask 等），并对你选定的钱包调用 eth_requestAccounts 取回一个公开地址；当前页不可用时会在后台打开 tapeout.firsto.ai 再探测一次。这一步不读取页面正文、图片、Cookie、表单、浏览历史或其它标签页，不签名、不请求授权额度、不发起链上交易，钱包弹窗由你自己在钱包里确认。也可以完全不装钱包，直接手动填一个公开地址。地址与链 ID 加密后只存本机；scripting / activeTab 两项权限仅用于这一次用户触发的探测。

1.5.5 TapeOut API 资产读取（只读、按你绑定的地址）：为显示「矿机台数 / 预估日产 / 持仓 BEM / 累计领取 / BNB / 市值」，扩展后台会向以下公开只读接口发起请求，请求里只包含你的公开钱包地址（路径或 JSON 参数），不携带 Cookie、认证头、API Key、页面内容、推文正文、设备标识或任何身份信息：

  • https://api-tapeout.firsto.ai/v1/account/{地址}/portfolio、/circuit-summary、/v1/pod/miners/{地址}、/v1/pod/claims/{地址}?limit=100（Firsto 的 TapeOut API v1 索引层，schemaVersion 1 / 2 兼容，按最新版本字段解析、旧字段兜底）；
  • https://api.tapeapi.fun/tapeapi/v1/{balance|tokenBalance|bnbUsd}（TapeAPI 3.0.0 公共签名读取，POST 的 params 里只有地址与 $BEM 合约地址；响应带签名回执，扩展只取其中的公开余额数字，未在本机验签，也不把它当作交易决策依据）。

1.5.8 X Layer / FabX 资产读取（同样只读、按同一个公开地址）：为在 BSC 六格之外另列一组 X Layer 数字（矿机台数 / 挖矿中 / 预估日产 FAB / 持仓 FAB / 待领 FAB / OKB），扩展后台向以下公开只读接口发起请求，请求里同样只有你的公开钱包地址与公开合约地址，不携带 Cookie、认证头、API Key、页面内容、推文正文、昵称头像、投票数据、设备标识或任何身份信息：

  • https://api.fabx.tech/v1/accounts/{地址}/mining（FabX 官方 TapeOut PoD 索引，GET；返回 $FAB 余额、逐台电路矿机的状态 / 待领 / 算力权重与全网排放数据，全部是公开链上 / 索引数据）；
  • https://rpc.xlayer.tech（备用 https://xlayerrpc.okx.com，仅在主节点失败时使用）：一次 batch 三个公开只读 JSON-RPC 调用 —— $FAB ERC-20 balanceOf、电路 ERC-721 balanceOf、原生 eth_getBalance（OKB）。合约地址取自 FabX 官方公开配置，不调用任何写入方法、不签名、不授权、不发交易。

$FAB 为 8 位小数；链上 RPC 读数优先、索引层读数兜底。「预估日产 FAB」是按当前全网算力权重占比在本机外推 24h 的估算值，不是收益承诺。两条链的请求并发且彼此独立，任一接口失败只影响对应链的显示，失败项在面板副行单独计数。

资产快照只缓存到本机 chrome.storage.local（2 分钟），点「↻ 读资产」才强制刷新；不上传给开发者、不写入账本、不与打卡数据关联。BSC 数据的接收方为 Firsto 与 TapeAPI 公共服务的运营方，X Layer 数据的接收方为 FabX 官方索引与 X Layer 公共 RPC 节点，各自按其服务条款处理这一个公开地址。

1.5.6 $BEM 信仰者打卡与全网账本（唯一会写入外部服务的功能）：必须先连接钱包才能点「支持 / 观望」。点打卡时，扩展后台向公开共享账本 https://tapepost-privacy.app.workbuddy.host/api/vote 提交 { day, stance, voterId, name, avatar, quote, at, clock }：day 是北京时间日期，stance 是 support / watch；voterId 是「小写钱包地址 + 日期」经 SHA-256 得到的不可逆哈希，每天轮换、用于同一地址跨设备当日去重，账本与开发者都拿不到明文钱包地址；name 是你自己填写的昵称（≤16 字）、avatar 是你从 32 款内置头像里选的编号（不含图片文件）、quote 是从扩展本机 10000 条话语文库里随机抽出的一句、at 与 clock 是打卡时间（ISO 与北京时间 HH:MM）。支持票的这四项内容会写入账本并在 /vote 公开页的「信仰者墙」上展示，请只填你愿意公开的内容；观望票只计数、不上墙，撤回会同时删掉墙上明细。打开弹窗时 GET /api/state 拉取按天票数与近 14 日信仰者墙。钱包地址、私钥、API Key、页面内容、推文正文、设备标识一律不发送。账本由开发者运营，除此之外不接收也不留存任何用户数据；账本地址可在设置里改成自建兼容服务，断网时降级为纯本机账本并在界面标注「本机」，联网后连同名片补投。点「𝕏 发布到 X」只是用 x.com/intent/tweet 预填话语 + 昵称 + 时间 + 账本链接打开新标签页，发送仍由你手动完成，扩展不调用任何发布接口。notifications 权限用于你开启的每日打卡提醒（默认北京时间 20:00，可关闭），通知文字不含个人数据。1.5.5 的旧口径（本机随机盐哈希、只提交日期 / 立场）已停用；1.5.5 及更早的历史票只有计数、没有名片，不会补造。1.5.7 起，名片可以随时修改并保存：修改昵称或内置头像后，若当天已投支持票，扩展会用同一 voterId 向同一 /api/vote 重新提交一次（quote / at / clock 沿用上次打卡值，只替换 name / avatar），账本按身份哈希去重，只更新公开墙上这一条明细，不重复计票、不改变连续打卡、不更换激励话语；断网时更新包暂存本机、联网后补投。这一过程不新增任何数据种类、第三方接收方或权限；「𝕏 发布到 X」的预填文案也会同步换成新昵称。请留意：修改后会覆盖当天已公开的那条名片，历史日期的公开明细不受影响。

1.4.13 行情链路（后台定时，纯只读）：为在面板顶端显示三项公开行情，扩展后台默认每 5 分钟（可设 1 / 5 / 15 / 30 分钟，也可手动点 ↻ 立即刷新）向以下两个公开只读接口发起 GET 请求。其中 $BEM 与矿机日产能价这两项数据都来自 Firsto（接口域名 api-tapeout.firsto.ai，数据页 tapeout.firsto.ai）；第三项 TapeUP 内盘价来自 tapeup.io，见下一段，与 Firsto 无关：

  • https://api-tapeout.firsto.ai/v1/analytics/bem?range=24h 与 /v1/circuit-holders?page=1：$BEM 现价与 TapeOut 矿机日产能价（后台 GET）。后者是 https://tapeout.firsto.ai/circuits/other 页顶「日产能价参考价」所用的同源公开接口；1.4.20 起替换原来的 /v1/analytics/circuits?range=24h（24h 成交序列，会滞后）。接口路径变了，但域名、请求方式与只读性质不变；

4. AI 功能：运行模式与数据流向

两个由你手动触发的 AI 功能（X 一键评论、链接真伪查询）支持「自动（默认）／站内直连／xAI API／DeepSeek API（1.5.3 新增）／页面模式（1.4.0 起已弃用，仅手动兜底）」。默认「自动」在未填 API Key 时走 1.4.2 的站内直连：由 X 页面自身向 X 自有的 Grok 接口发请求；填了 Key 才走 xAI API。「DeepSeek API」是显式选择的独立模式：选中后不降级到站内直连或页面模式，X 一键评论、链接真伪查询与「测试当前模式」都改走 DeepSeek。

① API 模式（xAI Grok）：需要你自己的 xAI API Key，扩展后台才会向 https://api.x.ai/v1（或你自填的兼容网关）发起请求：

  • X 一键评论：点击后把该条推文的正文 + 你设定的评论提示词发送给 https://api.x.ai/v1（或你在设置里填写的兼容网关），由 Grok 生成 3 条回复候选。候选只显示在本机浮层里；选中后才写入当前 X 回复框（1.3.1 起按钮位于回复填写区右侧，写入是页面内 DOM 操作，不产生新的网络请求），发送由你手动完成。
  • 链接真伪查询：点击核验后把待核验链接 + 插件本地比对得出的结论 + 与本次判定相关的少量清单条目 + 你设定的核验提示词发送给同一接口，由 Grok 生成解释与仿冒风险判断。最终是否给绿标由本地清单决定，不采信模型结论。

①-b DeepSeek API 模式（1.5.3 新增）：在设置 →「运行模式」显式选择「DeepSeek API」并填入自己的 DeepSeek API Key 后，扩展后台会向 https://api.deepseek.com/chat/completions（也接受 /v1 或你自填的兼容网关地址）发起 OpenAI 兼容请求。默认模型 deepseek-v4-flash，可换 deepseek-v4-pro；可开启「强制 JSON 输出」（response_format: {"type":"json_object"}），用不认该参数的兼容网关时关掉即可。官方 JSON Output 要求提示词里出现 json 字样：默认提示词已带；若用户自定义提示词删掉了，扩展会在本机自动补一条要求 JSON 输出的 system 提示，「预览实际发送内容」与真实请求保持一致，除此之外发送内容不变。Key、模型 ID、接口地址与该开关共四项，均保存在本机 chrome.storage.local，仅存本机、不同步、不随扩展分发、开发者无法读取，并且与 xAI 的 Key / 模型 / 网关完全隔离。发送内容与 xAI API 模式完全相同：你点选的推文正文（≤1200 字符）或待核验链接、插件本地比对结论、少量相关清单条目与你设定的提示词；接收方为 DeepSeek（或你自填的兼容网关），认证方式是你自己的 Authorization: Bearer Key。此模式不读取 X 登录态、不读取 ct0 / authorization、不向 X/Grok 发请求，也不与 xAI Key 混用；生成的 3 条候选与核验结论仍只在本机解析与展示。

② 页面模式（1.3.0 引入，1.4.0 起已弃用，仅作手动兜底）：扩展不向 xAI 或任何 AI 接口发送网络请求，也不读取 X 登录凭据。它只在你已登录的 x.com/i/grok（或 X 页面上的 Grok 浮窗）里，把设定好的提示词填入输入框、按需点击发送，并从该页面读取 Grok 回答的文本，在本机解析成候选。与 Grok 的对话由 X 自己完成并保存在你的 X 账号里，受 X 的服务条款与隐私政策约束；扩展不读取你的对话历史、其它标签页或账号信息。仅当你显式切到该模式、或站内直连与 API 都不可用时使用；此模式不产生 API 调用费用。

若自动发送或读取失败，可改用手动流程：插件只把提示词填进输入框 / 复制到剪贴板，由你自己粘贴发送，回答出来后再点「读取 Grok 回答」。所有 DOM 选择器都可在设置里修改。

1.3.2 起的结果校验：页面模式会用唯一任务标记确认提示词确实只写进了 Grok 输入框、确实被发送，并确认读回了回答块；任一环节不成立就明确报错，不会把 X 页面的侧栏文字或按钮文字当作 Grok 结果展示。点击后出现的等待浮层只显示进度与耗时，不上传任何数据；Grok 回答文本的解析全部在本机完成。

1.4.2 起的认证修复与同页通道复用：若用户在同一 X 页面另行安装了 X Viral Monitor，扩展可能优先调用它已暴露在页面内的 Grok 生成函数；该调用仍发生在用户本机浏览器里，请求接收方仍只有 X / Grok（同为 grok.x.com/2/grok/add_response.json，发送提示词与推文正文），不新增第三方接收方、不新增网络请求类型、不把会话或内容回传给 TapePost 服务器或该插件开发者，扩展后台仍只接收 3 条文本候选。401 / 403 时扩展会读取 X 返回的错误说明用于本机排错，并可能用 X 网页客户端公开 bearer 重试一次；错误说明只在本机显示，不上传。

1.4.1 起的运行模式自动纠正：旧版可能把「X 站内 Grok」保存为已弃用的「页面模式」，导致站内直连不生效。1.4.1 会在设置面板与后台读取配置时把该旧值按「自动 · 优先站内直连」处理，并可选择一次性写回本机设置（仅修改运行模式这一项，并写入一个一次性标记，用户之后主动选择不会被覆盖）。该过程完全在本机完成，不新增网络请求、不上传任何数据；对 X/Grok 的数据流向与本页 1.4.0 段落所述一致。

1.4.0 起的站内直连（请重点阅读）：「自动 / 站内直连」模式下，AI 评论与链接核验会以你当前已登录的 X 会话，从 X 页面直接向 X 自有的 Grok 接口 grok.x.com/2/grok/add_response.json 发送「提示词 + 你选中的推文正文或待核验链接」。随请求发送的是浏览器自动附带的 X 会话 Cookie 与 X 网页客户端固定请求头（含 ct0、authorization、x-client-transaction-id）；签名在你本机页面内由 X 自带模块生成，不经过 TapePost 服务器、插件后台或任何第三方，扩展后台只接收生成的 3 条文本候选。数据接收方仅为 X / Grok，受 X 的条款与隐私政策约束；对话被设为临时对话（isTemporaryChat），不写入你的 Grok 历史。若你填写 API Key 并切到「xAI API」模式，接收方改为 xAI（api.x.ai）；若使用旧的「页面模式」，对话发生在 X 页面内，扩展自身不新增网络请求。插件不读取你的 X 密码，也不做遥测；但会在该 X 页面内读取 ct0 认证 Cookie 并观察 X 自身请求头中的 authorization bearer 以复用会话（仅页面内存、不存储、不导出、不回传给开发者或第三方，接收方仅 X 自己），详见第 1 节与第 5 节。

1.3.4 起的正文清洗（仅指清洗步骤本身）：回复框内的按钮去重、插件界面文字剥离、推文正文提取全部在页面内 DOM 完成，不涉及任何网络请求、不新增第三方接收方、不上传推文正文或页面内容；清洗后只剩界面文字时扩展会取消生成并在本机提示，不会把该内容发送给 Grok。

1.3.3 起的连接自愈：重新加载扩展后，插件可能刷新已打开的 X / Grok 标签，或在后台新建 x.com/i/grok 标签，以恢复失效的页面内脚本。刷新与新建标签均为浏览器本地操作，不会上传页面内容、推文正文、X 登录凭据或任何其它数据，也没有新增第三方接收方；连接错误只在本机转成中文提示，不回传诊断信息。

生态面板的 295 条收录清单是内置在扩展里的静态数据：运行时不会访问 tapeout.link 或 web.tapeout.link 拉取清单，也不会把整份清单上传给 xAI；核验时只发送你输入的链接、本地结论和上述少量相关条目。

不会发送给开发者或任何第三方：浏览历史、其它标签页内容、图片/视频文件、账号密码、个人信息，以及认证凭证的副本或日志。需要区分的是：站内直连的请求由浏览器自动携带 X 会话 Cookie 与请求头（含 ct0、authorization）发给 X 自己（接收方仅 X/Grok），这是 X 网页客户端发请求的正常行为；扩展不存储、不导出、不回传这些值，也不会把它们发给除 X 之外的任何一方。页面模式同样不会把回答文本上传给任何服务器 —— 解析全部在本机完成。DeepSeek API 模式下，只有你点选的文字 / 链接、本地结论、少量清单条目与提示词发给你填写的地址；X 会话 Cookie、bearer、图片 / 视频文件与浏览历史都不会发给 DeepSeek。

第三方责任：API 模式下发送给 xAI 的内容受 xAI 的隐私政策与其服务条款约束；1.5.3 起发送给 DeepSeek 的内容受 DeepSeek 隐私政策与其服务条款约束，调用额度与费用由你自行承担；若填写第三方兼容网关，该网关运营方同样会收到内容，请先确认你信任它。站内直连与页面模式下，提示词与回答由 X 处理，受 X 的隐私政策与服务条款约束。扩展开发者在任何模式下都不接收、不留存这些内容。

你可以在设置面板里切换运行模式、删除 API Key、关闭「自动发送」或关闭「AI 评论」按钮。删除 Key 后 AI 功能会自动改用 1.4.2 的站内直连（若仍显式选着「DeepSeek API」模式，会明确提示先填 DeepSeek Key，不会偷偷改走 X/Grok）；只使用「一键转发」时扩展完全离线可用。站内直连需要 Chrome 已登录 x.com 且账号具备 Grok 权限。
